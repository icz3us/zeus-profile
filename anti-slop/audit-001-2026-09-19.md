# Antislop audit 001

Date: 2026-09-19

Scope: the shipped Next.js portfolio in `app/`, `components/`, and `hooks/`, reviewed against the antislop core plus the UI, human, responsive-layout, copywriting, and code-comment skills.

Design direction: `prompt.md` supplies a clear art direction built from ASCII graphics, Gen-X soft-club references, and editorial brutalism. The implementation has a specific identity, so this audit does not treat the fixed dark palette, monospace metadata, ASCII visuals, or editorial asymmetry as defaults without purpose.

Verification completed:

- `npm run lint`: pass
- `npm run build`: pass with Next.js 16.3.5
- Source-level interaction and accessibility review: completed
- Browser click-through: not completed because no browser runner is installed in the workspace
- Contrast calculations used the WCAG 2.x formula from the antislop human skill

## Findings

1. HIGH: Forbidden em dashes remain in user-facing copy. Rule R-02. Examples occur in page metadata, the About profile, the Contact headline, and project titles (`app/layout.tsx:22`, `components/About.tsx:29`, `components/About.tsx:70`, `components/Contact.tsx:37`, `components/SelectedWork.tsx:12`).

2. HIGH: Muted text fails WCAG AA at its rendered sizes. Rule R-25. `#646872` measures 3.49:1 on `#0c0d0e`, 3.25:1 on `#141618`, and 3.03:1 on `#1a1d20`, yet it is repeatedly used for 8px to 12px text; `#62829a` also falls to 4.47:1 on `#141618` and 4.17:1 on `#1a1d20`.

3. HIGH: Component boundaries do not meet the 3:1 non-text contrast requirement. Rule R-25. The shared `#25282e` border measures only 1.15:1 to 1.32:1 against the three dark surfaces, so controls, cards, and focus boundaries cannot be reliably distinguished.

4. HIGH: Project previews and project headings are mouse-only controls. Rule R-32. Click handlers are attached to plain `div` and `h3` elements without keyboard focus or Enter and Space handling (`components/SelectedWork.tsx:121`, `components/SelectedWork.tsx:172`, `components/SelectedWork.tsx:229`, `components/SelectedWork.tsx:278`).

5. HIGH: The project dialog does not manage focus as a modal. Rule R-32. Escape closes it, but the dialog has no accessible name, initial focus, focus trap, or focus restoration, leaving keyboard and screen-reader users in an ambiguous page state (`components/ProjectModal.tsx:50`).

6. HIGH: Several touch targets are smaller than 44 by 44 pixels. Rule R-03. The brand link, desktop toggles, mobile menu button, modal close button, footer back-to-top button, repository header link, and contact text links use compact padding without a minimum target size.

7. HIGH: The audio toggle does not control audio across the page. Rule R-26. Every component calls `useSoundEffects()` independently, so the Navigation instance updates only its own state while project, contact, lab, and footer instances remain disabled until they are separately remounted or changed.

8. HIGH: The copy-email control reports success before the Clipboard API succeeds. Rule R-26. `navigator.clipboard.writeText()` is neither awaited nor caught, so denied or unavailable clipboard access still displays `COPIED!` (`components/Contact.tsx:9`).

9. HIGH: The interface contains factual and performance claims without evidence in the project. Rules R-17, R-36, and R-38. Examples include `sub-second time-to-interactive`, `STRICT ACCESSIBILITY`, `VERIFIED 2026`, `RESPONSE SLA: WITHIN 24 HOURS`, `uncompromising speed`, hardened servers, secure synchronization, and real-time behavior. Each claim needs verifiable support or plainer wording.

10. HIGH: Full interaction verification is missing. Rule R-35. Lint and production build pass, but the repository has no browser test setup and this audit could not execute the required element-by-element desktop, mobile, keyboard, and modal click-through.

11. MEDIUM: Decorative motion runs continuously and exceeds the brief's restrained-motion intent. Rule R-19. Hero ASCII, lab ASCII, and the custom cursor keep animation frames active while off-screen; pulse and bounce loops never settle; JavaScript animation loops continue even when reduced motion is requested.

12. MEDIUM: The custom cursor restarts its effect and animation loop on mouse movement. Rule R-19. `targetPos` is effect state and an effect dependency, so every pointer update removes listeners, cancels the frame, and creates a new loop (`components/CustomCursor.tsx:13`, `components/CustomCursor.tsx:64`).

13. MEDIUM: Direction arrows are used as a default action decoration. Rule R-08. Repository links, both project actions, all modal actions, contact links, and the footer action repeat arrow glyphs without a distinct directional purpose.

14. MEDIUM: Pulsing status dots are decorative or overstate live status. Rules R-09, R-19, and R-31. The navigation and project cards use endless pulse indicators for section position or product labels rather than a changing live state (`components/Navigation.tsx:75`, `components/SelectedWork.tsx:128`, `components/SelectedWork.tsx:285`).

15. LOW: Several passages use inflated AI-style copy instead of specific evidence. Rule R-16. Phrases such as `high-performance reactive user interfaces`, `resilient server architecture`, `robust MVC systems`, `enterprise application backends`, and `micro-motion coalesce into human experiences` make broad claims and flatten the otherwise personal voice.

16. LOW: Source comments narrate visible structure and obvious control flow. Rule R-31. Comments such as `Navigation Header`, `Main Content Sections`, `Huge Brutalist Title`, numbered animation steps, column labels, and generator labels add scanning noise without explaining constraints or non-obvious behavior.
